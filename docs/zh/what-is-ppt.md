# 什麼是 PPT？

[English](../what-is-ppt.md) | [中文](./what-is-ppt.md)

---

本文說明人們所說的“PPT”究竟指什麼、人們為什麼製作簡報、PowerPoint 檔案如何構成，以及這種媒介適合或不適合哪些溝通任務。

它把 PPT 同時視為溝通媒介、可編輯檔案、傳遞載體和原生檔案結構，而不只是若干頁面。

## 1. “PPT”同時指代幾種不同物件

日常語境中的“PPT”是一個混合概念。討論時至少需要區分五種含義：

| 含義 | 定義 |
|---|---|
| PowerPoint | Microsoft 提供的創作、編輯、演示與協作軟體 |
| Presentation | 一次包含資訊、受眾、傳遞場景和預期結果的溝通活動 |
| Deck | 在活動前、中、後使用的有序、可編輯演示檔案 |
| Slide show | 被現場演示或自動播放的頁面序列，可包含轉場、動畫、旁白、影片和計時 |
| PPT/PPTX 檔案 | 儲存頁面、可複用結構、媒體、備註、批註、關係和演示行為的數字包 |

Microsoft 將 PowerPoint 描述為一種可以從空白或模板建立演示、組合文字、圖片、藝術元素與影片、新增轉場和動畫並與他人共享成果的工具。僅從這份能力列表就能看出，簡報並不是一疊靜態頁面。參見 [Microsoft 的 PowerPoint 簡介](https://support.microsoft.com/en-us/powerpoint/training/what-is-powerpoint)。

在本文中，**PPT 指 PowerPoint 這一類簡報產物及其溝通用途**，不只是舊版 `.ppt` 副檔名。

### 1.1 常見檔案型別

| 副檔名 | 用途 |
|---|---|
| `.ppt` | PowerPoint 97–2003 的舊版二進位制簡報 |
| `.pptx` | 當前無宏 PowerPoint 簡報包，也是現代 PowerPoint 主要使用的可編輯格式 |
| `.pptm` | 含宏的 PowerPoint 簡報 |
| `.potx` | 可複用的 PowerPoint 模板 |
| `.ppsx` | 開啟後直接進入幻燈片放映檢視的 PowerPoint 放映檔案 |

當前格式及用途見 [Microsoft 檔案格式說明](https://support.microsoft.com/en-us/powerpoint/file-formats-that-are-supported-in-powerpoint)。現代 `.pptx` 是 Office Open XML 包，其詞彙和打包方式由 [ECMA-376 / ISO/IEC 29500](https://ecma-international.org/publications-and-standards/standards/ecma-376/) 標準化。

## 2. 人們為什麼製作簡報

人們通常不以“得到一些頁面”為最終目的。他們希望改變受眾所知道、理解、相信、決定或採取的行動，並且經常需要留下一個組織可以繼續使用的成果。

```text
源材料 + 意图
→ 有顺序的论证或解释
→ 共同的视觉体验
→ 受众结果
+ 可编辑、可传播的记录
```

| 溝通任務 | 演示結束後希望發生的變化 |
|---|---|
| 告知 | 受眾知道此前不知道的事實 |
| 解釋 | 受眾理解某種機制、關係或原因 |
| 說服 | 受眾接受或認真考慮某個立場 |
| 決策 | 群體從多個選項走向明確選擇 |
| 對齊 | 參與者形成共同優先順序、語言和下一步 |
| 教學 | 學習者能夠理解、記憶或執行某件事 |
| 彙報與問責 | 利益相關者能夠評價進展、證據、風險和責任 |
| 動員 | 人們從意識到問題轉向採取行動 |
| 留檔與交接 | 組織獲得可審批、可審計、可複用的正式成果 |

一份 deck 可以同時承擔多種任務。真正需要澄清的不是“哪一個標籤勝出”，而是這些任務之間的關係：是否存在主導結果、它們如何互相支撐，以及按什麼順序發生。例如，一次“進展彙報”可以在同一條溝通鏈中彙報進展、暴露風險並請求決策。

組織溝通研究把提案、會議、報告等反覆出現的形式視為組織針對反覆出現的場景和目的形成的社會慣例。這個視角對 PPT 很重要：deck 不是中性容器，而是組織溝通實踐的一部分。參見 Yates 和 Orlikowski 的 [《組織溝通型別》](https://doi.org/10.5465/amr.1992.4279545)。

## 3. 為什麼使用 PowerPoint，而不是其他媒介

當一項任務同時需要下列多種屬性時，PowerPoint 具有獨特價值：

| 屬性 | 價值 |
|---|---|
| 順序 | 作者可以控制或建議注意力展開順序 |
| 模組化 | 頁面可以重排、隱藏、複製、替換和複用 |
| 多媒體組合 | 文字、圖示、資料、圖片、音訊和影片可以在頁面內組合；動畫呈現隨時間發生的變化，轉場連線頁面之間的切換 |
| 演講支援 | 備註、演講者檢視、計時和導航支援現場傳遞 |
| 閱讀支援 | 閱讀檢視、批註、備註頁、講義和共享支援非同步審閱 |
| 可編輯性 | 產物可以修改、本地化、擴充套件和改作他用 |
| 組織可移植性 | 同一產物可以穿過會議、評審、審批、歸檔和複用環節 |

PowerPoint 不應該成為所有資訊任務的預設選擇：

| 首要需求 | 通常更適合的主要媒介 |
|---|---|
| 很長、線性、可獨立閱讀的完整論證 | 檔案或報告 |
| 動態資料的即時探索 | 電子表格、Notebook 或儀表盤 |
| 開放式群體探索 | 白板或協作畫布 |
| 不需要編輯的固定重複播放 | 影片 |
| 互動導航和豐富使用者輸入 | Web 應用 |
| 有順序、視覺化、可編輯並且需要繼續流轉的溝通 | PowerPoint |

因此，媒介選擇必須由場景決定。“這能不能做成幾頁 PPT”不如“這個任務是否需要一份有順序、模組化、可編輯的簡報產物”有價值。

## 4. 一份 PPT 有不止一種生命

一份 deck 經常在生命週期的不同階段承擔不同作用：

| 階段 | Deck 的作用 |
|---|---|
| 活動前 | 思考、綜合、評審和排練工具 |
| 活動中 | 協調注意力和節奏的共同視覺介面 |
| 活動後 | 閱讀副本、決策記錄、講義、審批材料或複用來源 |
| 沒有現場活動 | 非同步閱讀、錄製、旁白或自動播放的演示內容 |

PowerPoint 本身提供不同的編輯、放映、演講者、閱讀、備註、講義和母版檢視。Microsoft 明確建議現場演示時使用帶私有備註的演講者檢視，沒有演講者時使用閱讀檢視檢視演示。參見 [為任務選擇正確檢視](https://support.microsoft.com/en-US/PowerPoint/training/choose-the-right-view-for-the-task-in-powerpoint)。

### 4.1 傳遞場景會改變設計

| 主要場景 | Deck 應最佳化的內容 |
|---|---|
| 演講者主導 | 遠距離可讀性、節奏、視覺錨點以及對口頭表達的補充 |
| 讀者主導 | 自解釋邏輯、明確上下文、更完整證據和可導航性 |
| 混合場景 | 明確主要模式，並用備註、附錄或補充細節服務次要模式 |
| 錄製或自動播放 | 旁白、計時、轉場、播放可靠性以及不依賴現場講者 |

不能假設同一頁面可以同時最優地服務四種場景。稀疏的演講者主導頁面可能無法獨立承擔決策記錄；密集的董事會材料可能無法在大螢幕上有效傳遞。必須先明確主要傳遞場景，再決定資訊密度和字型。

Microsoft 對[演講者備註和講義](https://support.microsoft.com/en-US/PowerPoint/print-your-handouts-notes-or-slides)、[旁白和計時錄製](https://support.microsoft.com/en-us/PowerPoint/training/record-a-slide-show-with-narration-and-slide-timings)以及[共享與共同創作](https://support.microsoft.com/en-us/powerpoint/training/share-your-powerpoint-presentation-with-others)的支援，也說明 PowerPoint 產物橫跨現場表達、獨立閱讀、傳播和複用。

## 5. PowerPoint 原生物件模型

`.pptx` 是由相互關聯的部件組成的包，不是每頁一張點陣圖，也不是一個巨大的單體 XML。Microsoft 的 [PresentationML 結構指南](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document)把 Presentation、Theme、Slide Master、Slide Layout 和 Slide 列為核心部件，並允許備註、講義、批註、媒體、轉場和動畫等附加部件。

```text
Presentation package
├── Theme
├── Slide Master A
│   ├── Slide Layout A1
│   │   ├── Slide 1
│   │   └── Slide 4
│   └── Slide Layout A2
│       └── Slide 2
├── Slide Master B
│   └── Slide Layout B1
│       └── Slide 7
├── Notes / Handouts / Comments
└── Media / Charts / Tables / Transitions / Animation / Audio
```

| 物件 | 職責 |
|---|---|
| Theme | 可複用的顏色、字型和效果 |
| Slide Master | 一組 Layout 共同繼承的格式和物件 |
| Slide Layout | 某類頁面的預設外觀、位置和佔位符 |
| Placeholder | Layout 上預先格式化、帶型別的內容容器 |
| Slide | 繫結某個 Layout 的一次具體內容例項 |
| Notes 與 Handouts | 可見頁面之外的演講者和受眾通道 |
| Package relationships | 連線頁面、Layout、Master、媒體、備註、批註及其他部件 |
| Presentation behavior | 順序、轉場、動畫、旁白和計時 |

Microsoft 把 Slide Layout 定義為承載格式、位置和佔位符的結構，並明確顯示其位於 Slide Master 之下。參見 [什麼是 Slide Layout](https://support.microsoft.com/en-US/PowerPoint/what-is-a-slide-layout)。

這個層級非常重要，因為視覺上正確的截圖仍然可能是一份結構很差的 PowerPoint。真正可用的 deck 還需要合理的物件邊界、繼承關係、可編輯性、包關係和演示行為。

## 6. 什麼是 PowerPoint 模板

Microsoft 區分 Theme 和 Template：Theme 提供協調的顏色、字型和效果；Template 則在 Theme 之上增加面向特定用途的內容和結構。參見 [Theme 與 Template 的區別](https://support.microsoft.com/en-us/powerpoint/understand-the-difference-between-powerpoint-templates-and-themes)。

由此可以得到一個實用原則：

> 模板之所以存在，是因為某種演示身份、結構或溝通場景預計會重複出現。

在實際使用中，一個 PowerPoint 模板可以組合多個可複用層次：

| 層次 | 提供的內容 |
|---|---|
| Theme | 協調一致的顏色、字型和效果 |
| Slide Master | 一組 Layout 共同使用的格式和固定物件 |
| Slide Layout | 某類重複頁面的佔位符結構和預設構圖 |
| 預置內容與示例 | 面向特定用途的起始頁面、固定措辭、示例和使用指引 |

模板可以減少重複設定、保持視覺與結構一致、編碼反覆出現的演示模式，並讓後續編輯和評審更加可預期。一份 deck 可以被複制或作為參考，但視覺相似本身並不會自動形成結構良好的模板。有效模板需要把穩定、可複用的決策與只屬於某一次演示的內容分開。

## 7. 什麼是好的 PPT

好的 deck 不能只用視覺精美來定義。質量至少包含以下層次：

| 層次 | 核心問題 |
|---|---|
| 事實 | 論斷、數值、來源和概念區分是否正確？ |
| 溝通 | 受眾、預期結果、核心資訊和行動要求是否明確？ |
| 敘事 | 頁面順序是否形成預期的理解、判斷或決策？ |
| 認知 | 人們是否能在不過載的情況下感知、處理並連線資訊？ |
| 視覺 | 層級、字型、留白、影像和資料圖形是否服務於含義？ |
| 原生與執行 | Deck 是否能夠可靠地演示、編輯、評審、複用和交付？ |

研究並不支援“圖片越多越好”這樣的普遍規則。Mayer 對多媒體學習研究的綜合指出，設計良好的文字與圖形組合可以改善理解，同時人的資訊處理容量有限。參見 [《多媒體學習》](https://www.cambridge.org/highereducation/books/multimedia-learning/FB7E79A165D24D47CEACEB4D2C426ECD)。

Bartsch 和 Cobern 發現，即使 PowerPoint 本身可能有幫助，不相關的圖片和聲音仍會損害記憶與學習。參見 [《課堂中 PowerPoint 演示的有效性》](https://doi.org/10.1016/S0360-1315(03)00027-7)。Kosslyn 等人發現，真實演示中經常違反可辨別性、有限容量和資訊變化原則，而且未經訓練的觀察者常常無法識別這些設計問題。參見 [《PowerPoint 演示的缺陷與失敗：心理學分析》](https://doi.org/10.3389/fpsyg.2012.00230)。

結論不是建立一個萬能頁面公式，而是一條由場景決定的質量原則：

> 每個元素都應該幫助目標受眾，在目標傳遞場景中完成目標認知或組織任務。

## 8. PPT 不是什麼

PPT 並不天然等於：

- 把一份檔案分頁後加上裝飾；
- 一組漂亮但互不相關的畫布；
- 演講者將要說的話的逐字稿；
- 視覺效果展示；
- 沒有後續生命的一次性放映；
- 只是帶有 `.pptx` 副檔名的扁平圖片；
- 因為頁面看起來一致就自動成為模板；
- 所有溝通任務的正確媒介。

如果使用者從軟體預設提供的頁面形式出發，而不是從受眾真正要完成的任務出發，PowerPoint 的慣例也可能反過來扭曲溝通。工具應該服務溝通模型，而不是根據工具按鈕倒推溝通模型。

## 9. 每個 PPT 請求都應該回答的問題

| 問題 | 為什麼重要 |
|---|---|
| 受眾是誰？ | 決定語言、預設知識、證據和語氣 |
| 看完後必須發生什麼變化？ | 定義溝通任務和成功條件 |
| 主要是現場講、獨立讀、錄製還是混合？ | 決定密度、字型、備註和演示行為 |
| 核心資訊是什麼？ | 防止在沒有論證時直接生產頁面 |
| 哪些證據必須可見或可追溯？ | 保護事實完整性和決策價值 |
| 什麼可以改變，什麼必須保留？ | 明確編輯邊界和評審預期 |
| 哪些內容必須可編輯或保持原生？ | 定義物件模型和交付要求 |
| 什麼會反覆出現？ | 決定是否需要 Theme、Master、Layout、預置內容，或根本不需要模板 |

這些問題應該先於對風格、版式、模板、動畫或製作方式的詳細決定。
